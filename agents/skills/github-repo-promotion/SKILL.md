# GitHub Repository Promotion

1. Use only the supplied GitHub evidence package: repository metadata, README excerpt, and releases.
2. Keep every factual claim traceable to an evidence URL. Mark unavailable facts as unknown.
3. Treat Star/Fork/Issue counts as dated snapshots, never as product quality proof.
4. Do not claim adoption, performance, security, compatibility, or user outcomes unless the evidence package explicitly supports it.
5. Produce a shared factual core before adapting formats:
   - Xiaohongshu: one chosen form (图文 or 视频), not both.
   - Douyin: video-first hook, shot list, and a real-video requirement.
   - WeChat: long-form explanation, source links, and structured HTML brief.
6. Keep repository URLs and source attribution in the draft; require human review before generating publish assets or publishing.
7. Public repositories only. Never request, expose, or embed a GitHub token in generated content.
