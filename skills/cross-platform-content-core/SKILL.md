# Cross-platform Content Core

Build one source of truth, then let each platform tell the story differently.

## Content atoms

Every package must contain:

- **Audience job**: what the reader wants to accomplish.
- **Single claim**: one useful conclusion, not a collection of themes.
- **Proof**: verified facts, examples, demonstrations, or reproducible steps.
- **Method**: 3–7 ordered actions.
- **Boundary**: when the advice does not apply.
- **Story/example**: only if sourced or supplied; never invent personal experience.
- **CTA options**: save/use, discuss, or continue reading—never forced private-domain diversion.

## Workflow

1. Audit the evidence package. Separate facts, audience language, hypotheses, and unknowns.
2. Pick one promise using:
   - demand strength;
   - usefulness;
   - proof availability;
   - content gap;
   - compliance risk.
3. Write a master explanation:
   - problem;
   - surprising or useful conclusion;
   - proof;
   - steps;
   - example;
   - limitation;
   - next action.
4. Define platform transformations:
   - **Douyin**: visual demonstration, 0–3 second Hook, fast beats, one payoff.
   - **Xiaohongshu**: search-first title, skimmable note, 6–8 saveable cards.
   - **WeChat**: thesis, mechanism, evidence, counterpoint, detailed implementation.
5. Produce an asset manifest without inventing paths or rights.

## Quality gate

- One content ID and version.
- Every factual claim has a source/status.
- No “爆款”, guaranteed result, fake urgency, or fabricated experience.
- The three platform briefs must not be copy-pastes.
- Preserve one recognizable core idea across all outputs.

## Output

Return only the JSON required by `docs/social-workflow/content-package.schema.json`.
Add these optional fields when useful:

- `audience_job`
- `content_atoms`
- `winning_pattern`
- `search_intent`
- `demonstration_plan`
- `platform_handoffs`
- `known_unknowns`
